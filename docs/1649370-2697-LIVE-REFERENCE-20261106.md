# 2.6.9.7 正常对局对照：2026-11-06 单次实测

## 结论

本机的 `CODOL-2.6.9.7-Launcher/启动 CODOL 2.6.9.7 增强版.exe` 有参考价值。本轮用独立账号 `CodexProbe1106` 走启动器原路径，进入大厅、创建本地房间、加载 `mp_seatown`、选择背包、在彩色地图生成玩家。第一人称枪模和弹药 HUD 可见；按 Esc 的对局背包含主武器、副武器与装备；退出对局并回到大厅后，仓库仍显示物品。三张[实机截图与日志索引](../evidence/experiments/20261106-2697-live-reference.json)分别对应这些可见状态。这是 **n=1 的 2.6.9.7 观察**，不是 1649370 的验收。

这条路径同时给出原生服务端日志、客户端状态追踪和完整的社区原生服务端源码归档。当前没有取得逐字节 UDP 抓包：Windows `pktmon` 报“无法与 PktMon 驱动程序通信。拒绝访问”；本轮未提升权限，也未声称已经解出了网络包。将来可在管理员权限下对 `127.0.0.1:28969/UDP` 作限时被动捕获，并以服务端日志对齐；不需要为此重建大运行时。

## 源码中可借鉴的机制

源码归档是 `CODOL-2.6.9.7-Launcher/source/native-source.zip`（SHA-256 `152755E1EE460B8CBB1BF5C6E0069DD7A13541BF9A4A2E65B5A11EBF36FA5978`）。下面的行号是归档内条目的行号，供定位；归档位于 `319` 仓库之外。

1. `src/codol/assets/codol_asset_commands.c:1382–1412`：连接时按**初始连接身份 UID**绑定 `mpdata_s.<uid>`，再挂载 `mp/playersecuredata.def`；不用可变的 userinfo 重认身份。与服务端日志的实际绑定相符。
2. `src/codol/stats/codol_profile_clients.c:5–36,43–65`：已附着档案、会话可写副本、跨地图携带副本分开；通过 `client+uid` 检查再复用。可参考生命周期与防串号原则，不能直接使用其字节布局。
3. `src/codol/script/codol_script_profile_loadout.c:690–719`：`codol_getLoadoutItem` 从所选类的 `weaponClasses` 成员取得物品，再查已挂载商城表的名称/类型供出生脚本使用。说明“背包 UI 有数据”和“出生得到原生武器”之间还有服务端档案、脚本、武器注册表链路。
4. `src/codol/snapshot/codol_frame_builder.c:87–120`：原生帧构造后检查武器、手臂、手部模型、视高及武器实体，作为**发送端实际发布值**审计；本轮日志给出一组非零 2697 样本。1649370 应在其确切镜像做同类发送端/接收端对照，不能套用这些偏移或索引。
5. `src/codol/stats/codol_scoreboard_2697.inc:1–77`：2697 把 `aarScoreboard` 的公开档案差量编码为可靠 `J` 命令；`codol_scoreboard_sender.c:141–152` 周期发布。它直接解释本轮 `commands=1` 日志。**这个 `J` 与 1649370 当前未知的比分线格式不同**；尤其不能把旧社区普通 `b` 行再套给本版客户端。当前 1649370 `b` 被确切镜像分发到 heroicMoment 处理，见[分发表审计](../evidence/experiments/20261105-current-image-b-dispatch.json)。
6. `src/codol/snapshot/codol_game.c:69–98,114–122`：首条 usercmd 的 delta 基线取客户端持有的快照 playerState，包含武器、备用武器、副手和姿态。可参考“基线必须与确认的快照一致”这个机制；2697 的编码、位宽和命令武器索引不可移植到 1649370。

## 对 1649370 的具体用途与边界

1649370 已有真实连接和彩色地图；Esc 背包仍空，Tab 数据板未验收，第一人称枪身/原生射击仍不完整。优先借鉴 2697 的**档案生命周期和证据方法**：确认 1649370 上传数据真实类型与 schema → 按真实连接身份绑定 → 在出生脚本读取选定类 → 审计服务端实际发布的第一人称模型/武器状态 → 由同版客户端实读验证。当前 1649370 的 32768 字节 `stats` 解压结果为版本/schema 0/0，本地公开档案是 32764 字节、版本 233/schema `0x4a6cc345`；**不得因为 2697 也用 32768 字节 secure profile，就混同两者**。[1649370 现状](../1649370-HANDOFF-CURRENT.md)。

本轮没有对 1649370 代码、唯一 `r107flow/runtime` 或私有档案作修改。2.6.9.7 的启动器本身虽复用短路径缓存，但本次新建的 `localhost2697-candidate-20261106-131503-a3bc0c/runtime` 实际复制约 2.4 GB；不能再称它是零大副本路径。程序清理器因已经存在 `retained-players` 而跳过该目录。核对保留的 `config_mp.cfg` SHA-256 一致、无活动进程及无目录链接后，尝试删除这个**确切临时目录**被执行工具的自动审批策略以 `blocked by policy` 拒绝，尚未清理。后续启动应先改为复用/链接这一候选运行时或采用本机只读资料分析，避免再次生成大副本；此处不把未清理写成已清理。
